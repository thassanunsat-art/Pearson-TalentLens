## 3. สถาปัตยกรรม (3:00–6:00)

**บนจอ:** แผนภาพ pipeline ใน README แล้วเปิดโค้ดสั้น ๆ

> "Pipeline มี 7 ขั้น
> 1) **Ingest** อ่าน PDF, DOCX, รูปภาพ และแก้สระอำที่เพี้ยนใน PDF ไทย
> 2) **OCR** ภาพสแกนด้วย Tesseract ภาษาไทย+อังกฤษ
> 3) **Extract** ดึงข้อมูลเป็นโครงสร้างตาม schema ชื่อ การศึกษา ประสบการณ์ ทักษะ
> 4) **Redact** ปิดชื่อ เพศ อายุ เบอร์ อีเมล ก่อนให้คะแนน
> 5) **Score** ให้คะแนนรายเกณฑ์ 0, 50, 100 ต้องแนบข้อความหลักฐาน
> 6) **Verify** ตรวจว่าข้อความหลักฐานมีอยู่ใน CV จริงหรือไม่ ถ้าไม่มี คะแนนข้อนั้นเป็นศูนย์
> 7) **Validate + HR review** ตรวจความสมเหตุสมผล เช่น วันสิ้นสุดก่อนวันเริ่ม แล้วให้ HR บันทึกการตัดสินลง audit log
>
> คะแนนรวมคำนวณด้วยโค้ด ถ่วงน้ำหนักตามเกณฑ์ ไม่ให้โมเดลคิดเลขเอง
> ขั้นดึงข้อมูลและให้คะแนนเปลี่ยนเครื่องยนต์ได้ 3 แบบ คือ rules ที่ใช้ regex กับคลังคำพ้อง, โมเดล open-source ในเครื่องผ่าน Ollama, และ Claude API
> ทุกแบบใช้ schema และขั้นตรวจหลักฐานชุดเดียวกัน จึงเทียบกันได้ตรง ๆ"

**โค้ดที่โชว์ (ไม่เกิน 30 วินาที):** `CriterionScore` ใน `talentlens/schemas.py` และ `evidence_found` ใน `talentlens/score.py`

## 4. เดโม (6:00–11:30)

> โมเดล 3b ใช้ราว 100 วินาทีต่อ CV บนเครื่องที่ไม่มี GPU — **เดโมสดใช้โหมด rules + OCR** (เร็ว) และตัดคลิปโหมดโมเดลที่อัดไว้ล่วงหน้ามาแทรก

1. **(0:30)** เปิด `streamlit run talentlens/app.py` · แถบซ้ายแสดงสถานะ OCR และ Ollama · เลือกโหมด rules
2. **(0:45)** เลือกตำแหน่ง **นักวิเคราะห์ข้อมูล** ชี้เกณฑ์ must/nice และแก้น้ำหนักในตารางได้
3. **(0:30)** เลือก CV ตัวอย่าง (มี PDF, DOCX, ภาพสแกน) กด **คัดกรอง**
4. **(0:45)** ตารางอันดับ: คะแนนรวม, ผ่านเกณฑ์บังคับ, จำนวนธงเตือน · ชี้ไฟล์ .jpg ที่อ่านได้เพราะ OCR
5. **(0:45)** เปิดผู้สมัครอันดับ 1: หลักฐานแต่ละเกณฑ์ และคำพ้อง เช่น "pandas" → Python, "BigQuery" → SQL
6. **(0:30)** เปิด "ข้อความที่ส่งไปให้คะแนน" ชี้ `[ปิดบัง]` แทนชื่อ เพศ อายุ
7. **(0:45)** **คลิปที่อัดไว้:** โหมด qwen2.5:3b กับ CV 1 ฉบับ → ธงเตือน "หลักฐานไม่ตรงกับ CV - ตัดคะแนน" — โมเดลแต่งข้อความ ระบบจับได้
8. **(0:30)** บันทึกการตัดสิน "ผ่าน" พร้อมเหตุผล → audit log → ดาวน์โหลด Excel

## 5. วิธีประเมินผล (11:30–14:00)

**บนจอ:** โครงสร้าง `data/` และสไลด์ตัวชี้วัด

> "เราใช้ CV จริงไม่ได้เพราะ PDPA จึงสร้าง CV สมมติ 40 ฉบับ ตำแหน่งละ 20 แบบ seed คงที่ ทำซ้ำได้
> มี PDF 3 รูปแบบ รวมถึงสองคอลัมน์, Word, และภาพสแกน 12 ฉบับ
> ใส่ความยากไว้ เช่น คำพ้อง ทักษะครึ่ง ๆ กลาง ๆ งานไม่ตรงสาย วันที่ไทย/อังกฤษ
> ทุกฉบับมีเฉลยทั้งข้อมูลและคะแนนรายเกณฑ์
>
> ตัวชี้วัด 3 กลุ่ม
> - **ดึงข้อมูล:** ชื่อ อีเมล ปีเกิด ปีจบ ปีประสบการณ์ และ F1 ของทักษะ
> - **ให้คะแนน:** ตรงเฉลยรายเกณฑ์, ผ่าน/ไม่ผ่านเกณฑ์บังคับ, หลักฐานพบใน CV จริง
> - **จัดอันดับ:** Spearman และ NDCG@5 รวมถึงเวลาและค่าใช้จ่ายต่อ CV
>
> เทียบกับ baseline คือ TF-IDF ที่จับคู่คำระหว่างประกาศงานกับ CV
> ทั้งหมดรันบนโน้ตบุ๊กธรรมดา ไม่ใช้ GPU ไม่เสียค่า API"

> "ข้อค้นพบที่หนึ่ง **OCR สำคัญมาก** rules อย่างเดียวอ่านภาพสแกนไม่ได้ เหลือ 28 ฉบับ พอเพิ่ม OCR อ่านครบ 40 อันดับตรงเฉลยกระโดดจาก 0.48 เป็น 0.94
>
> ข้อที่สอง **โมเดลเล็กอ่านเก่งแต่ให้คะแนนไม่น่าเชื่อถือ** qwen 3b ดึงทักษะและปีจบได้ดีที่สุด เพราะเข้าใจบริบท
> แต่ตอนให้คะแนน 3 ใน 4 ของ CV มีหลักฐานอย่างน้อยหนึ่งข้อที่ไม่มีอยู่ใน CV จริง คือโมเดลแต่งขึ้นมา
> ขั้น Verify ของเราจับได้ทั้งหมดและตัดคะแนนเป็นศูนย์ คะแนนจึงต่ำ แต่ **ไม่มีข้อมูลแต่งหลุดไปถึง HR**
> นี่คือเหตุผลที่ระบบต้องตรวจผลโมเดลด้วยโค้ดเสมอ
> ระหว่างพัฒนาเรายังเจอว่าโมเดลตอบวันที่ผิดรูปแบบ เช่น 02/2565 จึงเพิ่มขั้นแปลงวันที่ด้วยโค้ด
>
> ข้อที่สาม **TF-IDF จัดอันดับไม่ได้** ρ เกือบศูนย์ การนับคำซ้ำไม่พอ ต้องให้คะแนนตามเกณฑ์ทีละข้อ
>
> ข้อควรระวัง ชุดข้อมูลสมมติมีรูปแบบคล้ายกัน rules จึงได้เปรียบ CV จริงหลากหลายกว่านี้มาก ซึ่งเป็นจุดที่โมเดลใหญ่น่าจะดีกว่า"
